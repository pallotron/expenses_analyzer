# Gemini auto-categorize on the Merchants page — design

Ports the TUI's "Auto-Categorize Uncategorized" (`expenses/gemini_utils.py`,
`categorize_screen.py`) to the web. One PR. The Import port will reuse the
service later; wiring it into Import is not part of this work.

## Decisions (owner, 2026-10-03)

- **Suggestions save at once, flagged.** Each saved suggestion sets
  `merchants.category_suggested = 1` (a column D1 already has). The Merchants
  page's existing "suggested" badge and Suggested filter are where they get
  reviewed. This replaces "review before save" in `docs/WEB_PORT_PLAN.md`.
- **Scope:** one button sends every uncategorized merchant that has live
  rows. Categorized merchants are never sent or changed.
- **New categories are allowed,** as in the TUI. They are created with no
  spending type (counted as discretionary) and named in the result toast.
- **Synchronous call in the Worker.** No queue, no polling; the browser never
  sees the key.

## Worker

### `worker/src/domain/gemini.ts` (pure)

Ports, held to the Python by a new `gemini` section in
`worker/src/__tests__/fixtures/python_vectors.json` (generated by
`tools/crosscheck/vectors.py` calling the real `gemini_utils` functions):

- `categoryGuidance(categories: string[], type: TransactionType): string` ←
  `_build_category_guidance`.
- `geminiPrompt(names: string[], guidance: string, type: TransactionType): string`
  ← `_build_gemini_prompt`, byte for byte (whitespace included).
- `parseGeminiResponse(text: string, asked: string[]): Record<string, string>`
  ← `_parse_gemini_response` (strip code fences, `JSON.parse`), plus checks
  the Python lacks: the result must be a JSON object; only keys that were
  asked are kept; only non-blank string values are kept, trimmed. Anything
  else throws `GeminiResponseError`. Vectors cover the Python-equivalent
  part; the extra checks have their own tests.

### Gemini client

`worker/src/services/gemini.ts` exports
`type GenerateText = (prompt: string) => Promise<string>` and
`geminiClient(apiKey: string, model: string, fetchImpl = fetch): GenerateText`.
It POSTs to
`https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
with the key in the `x-goog-api-key` header (never in the URL), body
`{ contents: [{ parts: [{ text: prompt }] }] }`, and returns the joined text of
`candidates[0].content.parts`. A non-2xx status or a missing candidate throws
`GeminiCallError` carrying the HTTP status only. Nothing logs the key, the
prompt or the names.

### `worker/src/services/categorize.ts`

`suggestCategories(db, generate: GenerateText, userId): Promise<SuggestResponse>`

1. Read merchants with `category_id IS NULL` and at least one live row, with
   their type by the Merchants page's rule (income when
   `income * 2 > count`).
2. Per type, the guidance categories are the distinct non-archived category
   names already used by merchants of that type; if none, all non-archived
   category names. (The TUI read a static default list, which D1 does not
   have.)
3. Per type, call `generate` on chunks of at most 100 names, one chunk at a
   time. Every call must succeed before anything is saved; the first error
   propagates and nothing is written.
4. Save in one `atomic()` batch, the names passed as a single JSON parameter
   (`json_each`), never one bound parameter per name:
   - a suggested category matching an existing one case-insensitively takes
     the existing spelling ("groceries" → "Groceries"), so no near-duplicate
     is created; the rest are `INSERT OR IGNORE INTO categories (name)`;
   - `UPDATE merchants SET category_id = …, category_suggested = 1,
     category_set_by = userId, category_set_at = unixepoch()` for each
     answered merchant **where `category_id IS NULL`**, so a category set in
     the meantime is not overwritten.
5. Return
   `{ asked: number, suggested: number, newCategories: string[], unanswered: number }`.
   `suggested` counts merchants actually updated; `unanswered` is
   `asked - suggested`.

`confirmSuggestions(db, ids, userId): Promise<{ confirmed: number }>` sets
`category_suggested = 0, category_set_by, category_set_at` where the id is in
`ids` (`json_each`) and `category_suggested = 1`. The category is unchanged.

### Routes (`worker/src/routes/merchants.ts`)

- `POST /api/merchants/suggest` (empty body). 503
  `{ error: "Gemini isn't set up" }` when `GEMINI_API_KEY` is unset. On
  `GeminiCallError` or `GeminiResponseError`: 502
  `{ error: "Gemini didn't answer (HTTP 429)" }` /
  `{ error: "Gemini's answer couldn't be read" }`. Otherwise 200
  `SuggestResponse`. With no uncategorized merchants it returns zeros without
  calling Gemini.
- `POST /api/merchants/confirm` `{ ids: number[] }` (non-empty, positive
  integers, as the category route validates) → `{ confirmed }`.
- Both sit behind the existing Origin check.
- `GET /api/lookups` gains `gemini: boolean` — true when `GEMINI_API_KEY` is set.

### Config

- `AppBindings` gains `GEMINI_API_KEY?: string` and `GEMINI_MODEL?: string`.
- `wrangler.toml` `[vars]`: `GEMINI_MODEL = "gemini-2.5-flash"` (the TUI's
  hardcoded model). The route falls back to that value when unset.
- `GEMINI_API_KEY`: `worker/.dev.vars` locally, `wrangler secret put` in
  production (only with the owner's go-ahead).

Shared types go in `worker/src/api/merchants.ts`: `SuggestResponse`,
`ConfirmRequest`, `ConfirmResponse`.

## Frontend

- **Button:** on the Merchants page's count line, "Suggest categories", shown
  when `lookups.gemini` is true and at least one listed merchant has
  `category === null && count > 0`. While pending it reads "Asking Gemini…"
  and is disabled.
- **Result toast:**
  - `asked === 0`: "No uncategorized merchants".
  - otherwise "Suggested categories for N merchants", plus
    " · new: A, B" when `newCategories` is non-empty, plus
    " · M got no answer" when `unanswered > 0`; action **Review** sets the
    Suggested filter (`attention=suggested`).
  - error: the Worker's message with **Retry**.
- **Confirm:** the selection bar gains **Confirm**, shown when at least one
  selected merchant is `suggested`; it sends only those ids. Toast "Confirmed
  N merchants"; the selection clears.
- Writes invalidate the same keys as the other merchant writes
  (`MERCHANT_WRITES`), since a category change moves Summary and Transactions
  totals.

## Testing

- `domain/gemini.ts`: Python vectors (expense and income prompts, guidance
  with and without categories, fenced and bare JSON); extra checks (non-object,
  unasked keys, non-string and blank values).
- `services/gemini.ts`: request URL, header and body; text extraction;
  non-2xx and empty-candidate errors — with a fake `fetch`.
- `services/categorize.ts` with a fake `generate`: type split and per-type
  guidance; chunking at 100; new category created and flagged; merchant
  categorized meanwhile left alone; a failing chunk saves nothing; no
  uncategorized merchants makes no call; more than 100 merchants through
  `fakeD1`. `confirmSuggestions` clears only flagged ids.
- Routes: 503 without a key, 502 mapping, 200 shape, confirm validation,
  Origin check, `lookups.gemini`.
- Frontend: button visibility (key, uncategorized rows), pending state,
  toast text and Review, error Retry, Confirm visibility and ids sent.
- Before the PR: `wrangler dev` on a throwaway D1 copy with the owner's key in
  `.dev.vars` — a real Gemini call with the local uncategorized names, made
  only after asking the owner.

## Out of scope

- Wiring suggestions into Import (lands with the Import port).
- Re-asking Gemini for categorized merchants.
- Editing a category's spending type (Budget types screen).
